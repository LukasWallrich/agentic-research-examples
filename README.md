# Agentic research examples

> [!WARNING]
> **AI-generated research content.** All research content in this repository (study designs, code, analyses, manuscripts, cover letters and reviews) was generated by AI agents from a single brief. The examples are demonstrations of task completion for the tutorial "Easing into agentic AI in research". They have not been peer reviewed, and their scientific quality has not been evaluated. They are not intended for publication or for citation as research findings. Errors are known to exist. Each example lists its own:
>
> - `anchoring-extremity-opaq`: [weaknesses](anchoring-extremity-opaq/weaknesses.md), [deviations from the preregistration](anchoring-extremity-opaq/deviations.md)
> - `selective-feedback-simulation`: [weaknesses](selective-feedback-simulation/weaknesses.md), [deviations from the preregistration](selective-feedback-simulation/deviations.md)
> - `confidence-weighting-crowds`: [weaknesses](confidence-weighting-crowds/weaknesses.md), [deviations from the preregistration](confidence-weighting-crowds/deviations.md)

This repository holds three example research runs for the tutorial "Easing into agentic AI in research" by Lukas Wallrich. In each run, AI agents worked from a single brief to produce a judgement and decision-making (JDM) research paper without collecting new data: scoping, preregistration, analysis or simulation, manuscript, cover letter and AI review rounds.

Each folder keeps the agents' output with its full git history. The only later changes are the AI-generation warnings described below.

Each example folder contains its own `decision_log.md`, `novelty.md`, `deviations.md`, `review_log.md`, `ai_disclosure.md` and `weaknesses.md`, written by the agents, and an `AI_GENERATED.md` warning.

Facts that affect how the examples are read:

- **Human messages during the runs.** Each T3 Code thread contains the brief as its only user message. Before the `confidence-weighting-crowds` run, a separate Codex thread in the same folder diagnosed why the OpenCode command-line tool failed to start there. That thread is in the run records.
- **Commits after the run.** `selective-feedback-simulation` has two commits from 29 September 2026 (`8ebbf92`, `61ace46`). They remove 125 files inherited from `ai-jdm-paper` and append a dated note on the model identifier to `ai_disclosure.md`. The run itself ends at `5d1b072`.
- **Shared history.** The `ai-jdm-paper3` folder was set up from `ai-jdm-paper`. The history of `selective-feedback-simulation` therefore starts with the 12 commits of `anchoring-extremity-opaq`.
- **Commit authors.** The git author field reflects local git settings, not who wrote the content. Commits in the first two examples are authored as Lukas Wallrich. The commits of `anchoring-extremity-opaq` carry a co-author line for Claude Opus 5.5; the run commits of `selective-feedback-simulation` carry none. Commits in `confidence-weighting-crowds` are authored as "Research Agent". The agents issued the `git commit` calls during the runs (see the run records).
- **Preregistration.** Each plan is committed to git before the confirmatory analysis or hypothesis-testing simulation. None is registered on a public registry.

## AI-generation watermarks

Commit `WATERMARK_COMMIT` adds a warning to every manuscript and cover letter, on top of the imported history:

- PDF: a diagonal, semi-transparent watermark on every page ("AI-GENERATED DEMONSTRATION — NOT PEER REVIEWED — NOT FOR CITATION") and a footer line.
- HTML: a fixed banner at the top of the page.
- Word: a header on every page and a banner as the first paragraph.
- Markdown and Quarto sources: a banner at the top.

`tools/watermark_outputs.py` applies these marks. The unwatermarked files are in the final imported commit of each example (`89c45f5`, `61ace46`, `4afe867`) and in the parent of `WATERMARK_COMMIT`. For example:

```sh
git show 89c45f5:manuscript/manuscript.pdf > manuscript_original.pdf
```

## Verify the run order with git

The folders were imported with `git subtree add`. The original commits keep their hashes, author dates and messages. Each import is a merge commit whose second parent is the last commit of the source project.

List the imports and later commits:

```sh
git log --first-parent --format='%h %ad %s' --date=iso
```

List the commits of one example, with author and commit dates:

```sh
git log --format='%h %ad | %cd | %s' --date=iso 89c45f5   # anchoring-extremity-opaq
git log --format='%h %ad | %cd | %s' --date=iso 89c45f5..61ace46   # selective-feedback-simulation, without the inherited commits
git log --format='%h %ad | %cd | %s' --date=iso 4afe867   # confidence-weighting-crowds
```

Inspect a preregistration commit and the files it contains:

```sh
git show --stat a40911b
git show --stat 68c07e4
git show --stat 03f4d3a
```

In the original commits, files sit at the top of the tree, not under the example folder. `git log -- <folder>/` therefore shows only the import merge and later commits. Use the commit ranges above, or `git show <hash>:<path>` with the path as it was in the source project (for example `git show a40911b:prereg/preregistration.md`).

Git dates are set by the local machine and cannot be checked independently. The run records give a second, independent account of the order of events.

## Run records

Each example folder has a `run_records/` folder with the local session records of the run: T3 Code thread messages, the lead agent's transcript, subagent transcripts, and the transcripts of review calls to other models where they were stored. `run_records/README.md` lists each file with its source, session id, time range and model, and states the matching rules, the files left out and the redaction counts.

The records were exported with [`tools/redact_transcripts.py`](tools/redact_transcripts.py). It redacts email addresses, the author's ORCID iD, the home directory path, API keys and fragments of them, and the names of local project folders that are not part of this repository. It leaves out stored tool-output files, which hold fetched third-party texts. The transcripts keep the standing instructions that the agents loaded at start-up. They may contain quoted excerpts of third-party texts returned by tools.
